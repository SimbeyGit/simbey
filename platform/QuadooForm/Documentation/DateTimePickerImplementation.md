# DateTimePicker

`DateTimePicker` wraps the standard `SysDateTimePick32` Win32 control. It is
registered by QuadooForm.dll and appears in both the stand-alone Designer and
Studio palettes through the existing factory catalogue. Its new 20x20 calendar
and clock icon is an ordinary DLL icon resource; the shared palette scales it
for the designer DPI. No host-specific palette registration is necessary.

## Properties and events

| Property | Default | Meaning |
|---|---|---|
| DateTime | Current local time at construction | Local wall-clock date/time, serialized as `YYYY-MM-DDTHH:mm:ss.mmm` |
| Kind | Date | Date or Time |
| DateFormat | Short | Short or Long date format; retained while Kind is Time |
| DateMode | DropDown | DropDown or UpDown; native time mode always uses the spin control |
| Format | Empty | Optional Win32 custom display format; empty restores the locale/style format |
| ShowCheckBox | False | Display the native optional-date checkbox |
| Checked | True | Whether the retained DateTime is active |
| MinDate | Empty | Inclusive minimum date, `YYYY-MM-DD`; empty removes the limit |
| MaxDate | Empty | Inclusive maximum date, `YYYY-MM-DD`; empty removes the limit |

The inherited geometry, tab order, font, enabled/visible state, popup menu, and
keyboard/focus events work normally. Default logical size is 170x24 at 96 DPI.
BackColor and ForeColor are applied to the native month calendar when supported
by the Windows theme; the native picker retains normal themed field rendering.

`OnChange`, `OnDropDown`, and `OnCloseUp` use the usual named-delegate binding
model and have no event-specific arguments. Programmatic DateTime or Checked
changes emit one OnChange for an actual logical change. Native notifications
generated by synchronization are suppressed. Duplicate native notifications and
assignments of the current value do not emit another change. Construction and
design mode retain the framework's normal callback suppression.

Scripts use the existing generic property adapter, for example:

```text
DateTimePicker1.Kind = "Time";
DateTimePicker1.Format = "HH:mm:ss";
DateTimePicker1.DateTime = "2026-11-05T14:30:00.000";
```

DateTime assignments also accept `YYYY-MM-DD` (midnight) or
`YYYY-MM-DDTHH:mm:ss` (zero milliseconds), then return the full canonical form.
Values are local wall-clock fields, with no timezone conversion. Gregorian dates
from 1601 through 9999 are supported. Invalid dates, out-of-range assignments,
reversed limits, embedded NUL/newline format text, unmatched quotes, and custom
format callback fields (`X` outside quotes) are rejected before mutation.
Custom callback-format notifications are outside this implementation.

Changing a boundary clamps the current date if necessary, retaining its time of
day. A definition's initial date is similarly clamped to its boundaries. Clearing
Checked retains DateTime for subsequent rechecking, serialization, and style
changes. Checked=False requires ShowCheckBox=True. Removing the checkbox restores
Checked=True and emits one OnChange if that changes the checked state.

Style changes replace the native HWND through the existing transactional native
replacement path. C++ callers holding a borrowed HWND must reacquire it after
changing Kind, DateFormat, DateMode, or ShowCheckBox. COM identity stays stable.

## Public interface

The only ABI addition is optional `IQuadooDateTimePicker`, IID
`D25A0D6A-34B4-48EA-AB90-3C8AB72A0057`, queried from the component:

- GetDateTime / SetDateTime use SYSTEMTIME; the setter ignores wDayOfWeek.
- GetChecked / SetChecked expose the optional-date state.
- GetDateTime returns the retained value even when unchecked.

Existing interface IIDs, vtables, property types, JSON schema, and script adapter
interfaces are unchanged. Native runtime code has no QuadooScript dependency.
The implementation uses classic date/time-picker messages available on Windows
XP, VS2008 C++, and existing repository containers and ownership conventions.

## Focused validation

Build affected projects without rebuilding compiler/VM, JSON, or SimbeyCore DLLs:

```powershell
.\tests\platform\QuadooForm\build-application-lifetime.cmd Debug Win32
.\tests\platform\QuadooForm\build-application-lifetime.cmd Release Win32
.\tests\platform\QuadooForm\test-datetimepicker.ps1
```

The focused runner executes only `--datetime-picker-only` in the native harness,
shared Designer tests, Studio integration tests, and application/script tests.
Logs go to `tests\results\DateTimePickerLogs`. It does not run the existing suites.

Coverage includes native values/styles, date validation and inclusive limits,
checkbox retention, logical/native event deduplication, observer reentrancy and
destruction, DPI, JSON round trips, failed construction, factory/HWND/GDI/USER
cleanup, inline editing, palette icon scaling, Studio member generation and
project reopen, and property access through an actual QuadooScript VM.

Win32 Debug and Release validation passed, each with 172 native assertions,
10 Designer assertions, 4 Studio integration assertions, and 4 script assertions
(190 per configuration). Affected projects built with no errors or warnings.
Build/test logs are kept under `target` and `tests\results\DateTimePickerLogs`,
respectively. SimbeyCore, JSON, and compiler/VM dependency DLLs were not rebuilt.

Manual dropdown/calendar interaction, locale/theme appearance, and execution on
the Windows XP VM should also be checked on the target machine.
